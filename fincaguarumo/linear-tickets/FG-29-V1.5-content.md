# Linear Ticket Content: FG-29-V1.5

## Title
FG-29-V1.5: Implement Role-Based Model Provider System - Phase 1.5 (Benchmarking)

## Description
Phase 1.5 implementation of the role-based AI model provider system. This phase adds comprehensive benchmarking capabilities, automated health checks, and promotion recommendation infrastructure to support data-driven model management.

## Acceptance Criteria

### Benchmark Harness
- [ ] Implement comprehensive multilingual RAG benchmarking framework
- [ ] Support for all benchmark dimensions from FG-29 spec:
  - Query language handling (ES, EN, NL, RU, DE, mixed-language)
  - Retrieval relevance (Recall@5, MRR, nDCG@10)
  - Cross-lingual retrieval (ES→EN, EN→ES, NL→EN, EN→NL)
  - Grounded answer accuracy (exact match / rubric score)
  - Faithfulness (hallucination rate ≤5%)
  - Citation quality (precision ≥0.9)
  - Structured output reliability (≥98% validity)
  - Tool-calling robustness (≥95% success rate)
  - Latency (p50/p95 tracking)
  - Cost efficiency (cost per successful task)
  - Failure recovery (≥95% recovery, <5s failover)
  - Language style quality (≥4/5 each language)

### Dataset Integration
- [ ] Integrate public benchmark datasets:
  - MIRACL for core multilingual retrieval
  - MMTEB for broad embedding evaluation  
  - MLDR for long-document multilingual retrieval
  - MEMERAG for end-to-end multilingual RAG quality
  - BEIR for English zero-shot robustness baseline
- [ ] Support for internal domain-specific golden sets for hospitality/tourism content
- [ ] Mixed evaluation combining internal and public benchmarks

### Automated Testing
- [ ] Nightly smoke checks on small golden set for drift detection
- [ ] Weekly full benchmarks for promotion decisions
- [ ] Ad hoc benchmark triggering for new models or provider/version changes
- [ ] Automated benchmark result storage in `./benchmarks/results/` with timestamped subdirectories

### Promotion Infrastructure
- [ ] Weighted scoring system implementation:
  - Retrieval relevance: 20%
  - Cross-lingual retrieval: 15%
  - Grounded answer accuracy: 20%
  - Faithfulness: 20%
  - Structured output/tool reliability: 10%
  - Latency: 10%
  - Cost efficiency: 5%
- [ ] Promotion recommendation engine with guardrails:
  - Total weighted score beats incumbent by at least 5%
  - Faithfulness does not regress by more than 1%
  - Structured output validity does not regress below 98%
  - p95 latency stays within SLA
  - Failure recovery remains within 5 seconds
- [ ] Recommendation-only mode (no automatic promotion in this phase)

### Health Monitoring
- [ ] Enhanced health checking with benchmark validation
- [ ] Background health checks every 10 minutes
- [ ] Health status caching with configurable TTL
- [ ] Integration with existing circuit breaker system

### Reporting & Observability
- [ ] Benchmark report generation (JSON, CSV, optional PDF)
- [ ] Performance metrics tracking and alerting
- [ ] Historical benchmark data retention (90 days daily, 30 days hourly)
- [ ] Dashboard-ready metrics export

### Technical Requirements
- [ ] Benchmark execution isolation to prevent production impact
- [ ] Configurable benchmark timeout and resource limits
- [ ] Parallel benchmark execution support
- [ ] Benchmark artifact versioning and reproducibility

### Testing
- [ ] Unit tests for benchmark scoring algorithms
- [ ] Integration tests for dataset loading and processing
- [ ] Performance tests for benchmark execution time
- [ ] Validation tests against known benchmark results

## Dependencies
- FG-29-V1 (Phase 1 foundation must be complete)
- FG-29 parent ticket
- Access to benchmark datasets (MIRACL, MMTEB, MLDR, MEMERAG, BEIR)

## Notes
- This phase focuses on measurement and recommendation, not automatic promotion
- Benchmark results should be stored for historical analysis and trend detection
- Promotion recommendations require manual review and approval in this phase
- All benchmark configurations should be environment-aware (dev vs prod)
